Cache Bar 多 Session 修复演示

Claude Code 的 statusline 显示缓存命中率柱状图。当多个 session 共享同一个 log 文件时， 累积计数器会出现"倒退"（175→169→176），导致命中率显示为 0% 或 >100%。 本修复实现了多 segment 支持，正确合并所有 session 的数据。

问题复现

BUG 原始实现：单 Segment 假设

1790853396 183 1 1790853400 184 1 1790853413 185 1 1790854071 1 0 ← 跳回 1（新 session 开始） 1790854121 223 1 ← 跳到 223（另一个 session） 1790854171 680 41 ← 跳到 680（当前 session） 1790854182 224 1
原代码使用 monotonic filter：一旦检测到倒退，丢弃所有旧数据。 结果：只保留最后 2-3 分钟的数据 → 显示 hit 100%（样本不足）或 hit 0%（负 delta）。

BUG 负 Delta 导致 >100% 命中率

bucket 4: dq=100 dm=-20 hit=120.0% bucket 7: dq=100 dm=-70 hit=170.0% bucket 9: dq=-956 dm=-21 Final: total_miss=-18, hour_pct=101.9%
原代码累加逻辑：if (have[i] && dq[i] > 0) 允许 负的 dm[i] 累加。 当 session 切换时，dm = m[i] - m[i-1] 可能为负 → total_miss 为负 → 命中率超过 100%。

修复方案

FIXED 多 Segment 识别与合并

❌ 旧逻辑

# 检测倒退 → 丢弃所有旧数据 if (f[2] < last_q || f[3] < last_m) { n = 0 # 重置样本数 continue }

✅ 新逻辑

# 检测倒退 → 保存当前 segment if (f[2] < last_q || f[3] < last_m) { seg_id++ # 开始新 segment num_segments++ }
使用二维数组存储多个 segment：t[seg_id, i]、q[seg_id, i]、m[seg_id, i]。 遍历所有 segment 计算 delta 并累加到对应 bucket。

FIXED 过滤负 Delta

❌ 旧逻辑

if (have[i] && dq[i] > 0) { total_req += dq[i] total_miss += dm[i] # 可能为负！ }

✅ 新逻辑

if (have[i] && dq[i] > 0 && dm[i] >= 0) { total_req += dq[i] total_miss += dm[i] }
添加 dm[i] >= 0 检查，过滤掉 session 切换时产生的负 delta。 防止 total_miss 为负，确保命中率在 0-100% 范围内。
